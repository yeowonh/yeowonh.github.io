## 문제

학교가 이미 공개한 기본 정보도 학생이 찾기 어려운 경우가 많습니다. 공지는 한곳에, 학사 규정은
다른 곳에 있고 학생에게 필요한 답은 여러 정보를 조합해야 얻을 수 있습니다. 학생들은 이미 존재하는
정보를 찾는 데 불필요한 시간을 쓰고 있었습니다.

## 접근 방식

팀장으로서 모호한 학생의 요구를 실제 베타 서비스로 전환하는 전 과정을 맡았습니다. 문제 정의,
데이터 수집, 모델링, API 개발을 연결했습니다.

- **모델보다 사용자 문제를 먼저 정의했습니다.** 학교가 이미 공개한 정보와 학생이 실제로 찾을 수
  있는 답 사이의 간극에 초점을 맞췄습니다.
- **전체 구현 흐름을 이끌었습니다.** 코퍼스, 모델링, API 작업을 조율해 프로토타입에 머무르지 않고
  실제로 사용할 수 있는 베타 서비스까지 완성했습니다.
- **실제 피드백으로 우선순위를 정했습니다.** 출시 후 재학생과 졸업생의 피드백을 수집해 다음 개선
  항목을 결정했습니다.

## 성과

- **외부 검증 | Sejong University 제15회 창의설계경진대회 우수상, 2위 수상.**
- **엔드투엔드 실행 | 문제 정의에서 동작하는 베타 서비스까지 완주.** 코퍼스 구축, NLP 모델링,
  API 제공을 하나의 제품 계획으로 연결했습니다.
- **사용자 피드백 | 재학생과 졸업생의 의견으로 다음 개선 우선순위 결정.** 내부 가정 대신 실제
  사용자 근거를 제품 반복 개발에 반영했습니다.
